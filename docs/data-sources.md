# Data Sources

AGENT.md の要約から分割した、外部データ取得元に関する決定事項。
「どこからデータを取るか」を集約し、「取ったデータをどう分析するか」は [`technical-analysis.md`](./technical-analysis.md) を参照。
Non-negotiable rules・優先順位は AGENT.md 側が正であり、本ファイルの内容と矛盾する場合は AGENT.md を優先する。

## Market scope
対象は日本株。

スキャン対象(仮決定): 東証上場の国内普通株のみ。ETF、ETN、REIT、優先株、外国株扱い、整理/上場廃止銘柄等は当面対象外とするが、将来含められるよう設定・フィルタ可能な構造にし、勝手に固定仕様へしない。

銘柄マスタ(コード・銘柄名・市場区分)の取得元(仮決定): JPX公式の上場銘柄一覧(無料CSV/Excel)を定期ダウンロードして更新する。ファイル形式変更に備え、取得処理は Infrastructure 層に隔離する。

信用売り候補では、テクニカルな `Short Entry` と「実際に売建可能か」を別情報として扱う。
信用取引対象区分・売建可否・規制情報の取得元(仮決定): JPX公式の信用取引銘柄・貸株銘柄一覧(無料CSV)を定期取得する。取得不能時は「不明」として扱い、売建可能と推測表示しない。

## Margin contract and carrying-cost data
制度信用の返済期限は最長6か月だが、一般信用の期限・品貸料・権利処理は証券会社との契約で決まるため、期限や料率をアプリ共通の固定値にしない（[JPX 信用取引制度の概要](https://www.jpx.co.jp/equities/trading/margin/outline/)）。正本は利用者が確認した証券会社の商品条件・取引明細とし、証券会社、商品、適用期間、日数計算規約、確認日時、根拠を版管理する。

制度信用の品貸料（逆日歩）はJPX/日本証券金融の公表値を取得・突合に使う（[JPX 品貸料](https://www.jpx.co.jp/markets/statistics-equities/margin/01.html)、[日証金 逆日歩の説明](https://www.taisyaku.jp/about/backwardation/)）。日々の入札後に確定するため事前予測値とせず、公表値が品貸日数込みの場合は日数を再乗算しない。`0.00`（0銭品貸し）、不発生、未公表、取得失敗を別状態にし、欠損を0円扱いしない。一般信用へ制度信用の逆日歩を自動適用せず、証券会社固有の特別空売り料等は別の契約コストとして扱う。

制度信用の配当金相当額は制度上の権利処理を参照し、一般信用は証券会社の契約を正とする（[JPX 制度信用の権利処理](https://www.jpx.co.jp/equities/trading/margin/rights/02.html)、[JPX 一般信用の権利処理](https://www.jpx.co.jp/equities/trading/margin/rights/01.html)）。税率を固定せず、gross、税額相当、net、実際の証券会社計上額を分離する。

## Price data
株価取得元は交換可能な抽象化を用いる。日足の最低項目は `Date/Open/High/Low/Close/Volume`。

取得元(仮決定): Yahoo Finance 非公式 chart API (`query1.finance.yahoo.com/v8/finance/chart/{code}.T`) を C# から HttpClient で直接呼び出す。
- 正本は取得時点の未調整 `Open/High/Low/Close/Volume` とし、取得元、取得日時、revision を付けて保存する。訂正データで過去値を上書きせず、どの版を分析に使用したか追跡可能にする。
- provider の `adjclose` は検算・障害調査用の参考値として保存してよいが、指標計算・シグナル判定の入力には使用しない。provider が後日再スケールしても保存済み判定を変えないためである。
- 初回取得は原則として上場来の有効な日足を対象とし、以後は差分更新する。取得元の制約等で履歴の完全性を確認できない場合は `HistoryIncomplete` とし、任意の取得開始日を EMA の起点にしない。
- 非公式APIのため、エンドポイント仕様変更・レート制限・アクセス遮断のリスクを前提に、取得処理は Infrastructure 層に隔離し、抽象化（インターフェース）越しに差し替え可能にする。

考慮:
- 株式分割・併合、調整後株価
- 欠損、訂正データ
- API rate limit、timeout、network error
- 企業アクションによる不連続のサイン誤検出防止

## Corporate actions and analysis prices
企業アクションは日足と分離して版管理する。最低限、銘柄、種別（分割・併合・現金配当）、効力発生日、発表日時、利用可能になった日時、初回観測日時、分割比率または配当額、通貨、取得元イベントID、revision、状態を保持する。訂正は旧版を削除・上書きせず、新版から旧版を supersede する。

分析日の確定済み日足を `D`、分析実行時点を `A` としたとき、分析系列には `effective_date <= D` かつ `available_at <= A` の企業アクションだけを適用する。過去バックテストでも各時点の `A` を再現する。履歴データに `available_at` がなく当時の利用可能性を証明できない場合は `PointInTimeUnverified` とし、正式な成績検証へ使用しない。

- 分割比率 `r = 新株数 / 旧株数` は、効力発生前の OHLC を `r` で割り、出来高を `r` 倍して、評価日時点の株式単位へ揃える。複数イベントは累積係数を使う。
- 現金配当は、権利落ち直前終値 `C` と1株配当 `d` から `f = (C - d) / C` を求め、権利落ち前の OHLC に `f` を適用して機械的な配当落ちギャップを除く。出来高と保有株数は変更しない。`C <= d`、欠損、通貨不一致の場合は推測調整せず要照合とする。
- 指標計算には同じ point-in-time 調整済み OHLCV を一貫して使う。最新バーの価格単位は未調整の市場価格と一致させ、ATR と利用者入力の約定価格を同じ通貨・株式単位で扱えるようにする。

保有中の分割・併合は、利用者が登録した元約定を変更せず、企業アクション調整履歴として現在基準の株数、取得単価、固定ATR、損切・利確ラインへ同じ分割係数を適用する。端株・現金交付、合併、スピンオフ等の未対応イベントは `ReconciliationRequired` とし、推測で分析や売買履歴を生成しない。

## Fundamental data
ファンダメンタル情報取得元(仮決定): Yahoo Finance の企業情報エンドポイント(非公式、株価取得と同じソース系統)から PER/PBR/時価総額等の構造化データを取得し、アプリ側で保持する。決算詳細・ニュース・業績予想等の非構造化情報は Codex CLI(AI)自身の調査に委ねる（詳細は [`ai-analysis.md`](./ai-analysis.md) を参照）。取得不能時は当該項目を欠損として扱い、AI 結果を無効にしない。

## Date/time
基準は日本時間 (`Asia/Tokyo` / JST)。
「分析日」「価格データ日」「約定日時」は別概念として扱う。
企業アクションの「発表日時」「利用可能になった日時」「初回観測日時」「効力発生日」も別概念として扱う。
信用コストの「申込日」「対象期間」「公表日時」「証券会社計上日時」「利用可能になった日時」も別概念として扱う。
土日だけでなく日本市場の休場日を扱える構造にする。
15:30 を過ぎただけでデータ確定済みと断定しない。
DB 保存時は日時のタイムゾーンの意味を曖昧にしない。
